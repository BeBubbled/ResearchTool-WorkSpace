## 0. 结论速览

1. **外壳本身已经对了，问题在每页自带的“页头 + 宣传语”。** 左侧 72px 导航栏（`_client_nav.html`）相当于 Xcode、Teams 那类“模块切换栏”，方向没问题。但几乎每个模块又各自加了一层品牌条或大标题，比如 `topbar`、`reader-header`、`prompt-topbar`，以及“用中文推敲，把英文写准确。”这类 hero 文案，首屏高度被吃掉一大块。macOS 应用的做法是：**窗口顶部只有一条工具栏，介绍文字只出现在空状态里。**
2. **统一成 macOS 的三栏骨架：侧边栏 / 内容 / 检查器（Inspector）。** 精读、改稿、文献库、研究空白、Studio 本质上都是“列表或结构 → 主内容 → 详情和 AI”。现在每个模块各写各的栅格（`reader-shell`、`columns`、`prompt-grid`、`project-rail` 等），面板能不能收起、宽度记不记得、开关按钮放在哪，都不一致。
3. **设置要分成三层：全局设置、模块默认值、当前视图的临时调节。** 现在精读的“阅读设置”面板里混着字体排版（视图级）、默认划词动作（模块级）、每个动作用哪个 LLM（应属引擎级）。改稿的“工作流”和使用确认铺在主界面上。Three-Pass 的引擎、模型和计费确认嵌在两层 `<details>` 里面。
4. **全局设置的 9 个标签是按供应商平铺的**：LLM、Mathpix、Codex、Claude Code、Google、双语改稿、Three-Pass、Azure、GitHub，把“账号和服务”与“功能偏好”混在了一起。可以学 macOS 系统设置（侧边栏加搜索），或者 Raycast 的分组加子页面 ✅，再加上 Bob 那种“服务列表 + 逐项配置” ✅ 的做法。
5. **菜单层几乎是空的。** 没有 ⌘K 命令面板，没有右键菜单，没有快捷键表，“更多”是一组藏起来的入口。Mac 用户靠菜单栏和快捷键发现功能。网页里的对应做法是：**命令面板 + 右键菜单 + 工具栏上的“…”溢出菜单 + 快捷键表。**
6. **工具箱页有两层导航**：72px 导航栏之外还有一条 320px 的深色侧栏，合计 392px。应改成 DevUtils / DevToys 那种结构 ✅：一个可搜索、可收藏的工具列表，配上统一的“输入 → 选项 → 输出”工具页。

### 1.3 跨模块的共性问题

- **同一类东西，在不同模块用了不同容器**：引擎、模型、计费确认在改稿里是工具条加复选框，在 Three-Pass 里是嵌套 details，在 Studio 里是表单里的复选框。历史和版本在改稿里是卡片，在 Studio 里是下拉框，在工作区里是标签页。
- **右侧辅助面板没有统一规则**：精读解读栏可以拖宽（280–420），改稿批注是覆盖式抽屉，研究空白的详情抽屉也是覆盖式，设置是 980px 抽屉。
- **面板开关的状态不记忆或不统一**：只有精读做了目录自动收起和宽度控制。
- **说明文字太多**：大量 `.hint` 段落一直显示，帮助信息和界面挤在同一层。

## 2. 对标应用：它们怎么排版

每个对标应用都从三个方面看：**内容布局**、**设置布局**、**菜单 / 命令**，最后写可以借鉴什么。

### 2.1 外壳：macOS 的窗口骨架

**Apple HIG 和 macOS 26 Liquid Glass** ✅
- 内容布局：标准是 `NavigationSplitView` 的“侧边栏 + 内容 + 检查器”。系统会给侧边栏和检查器自动加玻璃材质；**导航层（侧边栏、工具栏）浮在内容层上，内容本身不加玻璃**。带工具栏的窗口圆角更大，玻璃按钮按功能分组（用 ToolbarSpacer 分隔）。
- 设置布局：设置放在 App 菜单里，快捷键 ⌘,，**不要在工具栏放设置按钮**。设置窗口用工具栏切换各个面板，标题显示当前面板名，**重新打开时回到上次看的那个面板** ✅。
- 菜单：菜单栏固定是 App / 文件 / 编辑 / 显示 / 窗口 / 帮助。“显示”菜单里放侧边栏和检查器的开关，所有命令都能在菜单里找到，并标出快捷键。

**Xcode**（复杂多面板应用的范本）
- 内容布局：左边导航区有一排图标切换不同导航器（文件、搜索、问题、报告），中间编辑区可以分屏，右边检查器有一排图标切换（文件、帮助、属性），底部是调试区。工具栏左右两端各有一个按钮，分别开关左右面板。
- 设置布局：设置窗口顶部一排图标标签（General / Accounts / Behaviors / Text Editing…），其中 **Accounts（账号）单独一页**，和编辑偏好分开。
- 菜单：⌘0 开关导航区，⌥⌘0 开关检查器，⌘1…9 切换导航器。Open Quickly（⇧⌘O）就是命令面板。

**借鉴：**
- 导航栏保留，但每个模块页面统一成一种结构：**一条工具栏 + 可选左侧边栏 + 内容 + 可选右侧检查器**。左右面板的开关固定在工具栏两端，状态按模块记住。
- 设置按 Xcode 的思路拆开：**“账号与引擎”是一页，“功能偏好”是另一页**。

### 2.2 精读：PDF 阅读 + AI 解读 + 翻译 + 笔记

| 对标 | 内容布局 | 设置布局 | 菜单 / 选区 |
|---|---|---|---|
| **PDF Expert** ✅ | 左侧栏一个分段控件切换缩略图、目录、批注、书签，批注按页列出。页面布局和分屏按钮在工具栏右上，同一文件可以分屏打开 | 选中批注工具后，右侧出现颜色和透明度侧栏，**属性跟着当前工具出现** | 工具栏中间是模式（批注 / 编辑 / 填表…），右键菜单可以复制和粘贴批注 |
| **Highlights** ✅ | 工具栏是中心：缩略图、标注工具、笔记都从这里进。macOS 26 版改成透明工具栏加浮动侧边栏。右侧笔记栏自动汇总高亮，可导出 Markdown、Obsidian、Notion | 设置窗口按导出格式和模板分页 | 选中文字后弹出很小的颜色条（几个颜色点加少量动作） |
| **Zotero 7/8 阅读器** ✅ | 左侧栏是注释、目录、缩略图。右侧是条目面板，边上一列图标（sidenav）用来跳到信息、摘要、附件、笔记、相关等分区。**图标列跟着侧栏一起收起，内容区拿到全部宽度**。Zotero 8 支持拖动图标给分区排序，并记住上次打开的侧栏标签 | 设置是独立窗口，左侧栏分 General / Sync / Export / Cite / Advanced | 选中文字后弹出颜色、加入笔记、复制 |
| **Readwise Reader** ✅ | 左边目录，中间正文，**右侧栏用标签切换 Info / Notebook / Chat**（连按两次 ` 键轮换），右栏可以拖宽，Info 始终对应当前文档 | 正文排版通过工具栏的“Aa”弹出层调整：字体、字号、行高、宽度 | 选中文字后有一条极简工具条：高亮、笔记、标签、Ghostreader（AI），全部有单键快捷键 |
| **MarginNote 4** ✅ | 文档和脑图左右分屏，比例可调，可以收起上、下或中间一栏。沉浸模式下界面收成一个“胶囊”，切换读 / 写 / 复习 | 学习集级别的设置 | 卡片上的上下文菜单 |
| **Apple 图书 / Safari 阅读器** | 正文占满，工具栏会自动隐藏 | “Aa”弹出层：主题色、字体、字号，**即时生效，不需要保存** | ‑ |
| **Bob / 沉浸式翻译**（翻译层） | Bob 是浮动结果窗，多个服务的结果上下排列；沉浸式翻译在网页里做双语对照（段落交替、左右对照、只看译文） | Bob 设置里有“服务”页，翻译、OCR、TTS 服务各自列成清单，每个服务单独配置 ✅ | 服务图标右键直接跳到对应的服务设置 ✅ |

**借鉴（精读）：**
1. **右栏改成 Readwise 那样的标签式检查器**：`解读（Chat） / 笔记（Notebook） / Three-Pass / 信息`。Three-Pass 从两层 details 里提出来，单独占一个标签；笔记从可展开区提升为标签。右栏宽度和最后打开的标签都记住，学 Zotero 8。
2. **阅读设置拆成两部分**：
   - 工具栏放一个 **“Aa”弹出层**：字体、字号、行距、页宽，即时生效，学图书和 Readwise。
   - 页眉 / 正文 / 页脚的 12 个边距、默认划词动作、每个动作用哪个 LLM，这些搬到 **设置 › 精读**，因为它们是模块默认值，不属于当前视图。
3. **工具栏三段式**：左边是“目录开关 + 文档标题（点开是最近文档菜单）”；中间是**视图模式**，5 段可以压成一个“原文 ▾”下拉或 3 段加“更多”；右边是缩放、朗读、Aa、检查器开关。朗读的开关、停止、语速收成一个朗读按钮，点开弹出层。
4. **选区菜单分两级**：第一级像 Highlights / Readwise，一条约 40px 高的工具条：4–5 个颜色点、笔记、解读 ✦、更多 …。第二级在“更多”或 ✦ 里展开 Prompt 动作、送到 ChatGPT 和文字格式。
5. **导入状态和阅读状态分开**：导入页本身就是“空状态”加“最近文档”列表；论文打开后，导入相关的界面完全消失。学 Highlights 和 Zotero：最近文档放进标题菜单或文献库。

## 3. 统一布局规范（提案）

### 3.1 页面骨架

```
┌──┬───────────────────────────────────────────────────────────────┐
│  │ 工具栏 48px： [⊞左栏] 标题/项目 ▾   │  模式分段  │  操作 … [主按钮] [⊟检查器] │
│导│───────────┬───────────────────────────────────┬───────────────┤
│航│ 侧边栏     │ 内容                              │ 检查器         │
│栏│ 220–280px  │ （最小 480px，自适应）             │ 300–420px      │
│  │ 可收起     │                                   │ 标签：图标+文字 │
│72│ 记住状态   │ 空状态里才放介绍文字               │ 可拖宽，记住宽度 │
└──┴───────────┴───────────────────────────────────┴───────────────┘
```

- **工具栏**：每页只有一条，固定 48px，从左到右依次是：左栏开关、标题（点开是标题菜单）、居中的模式分段控件、操作按钮、主按钮、检查器开关。去掉各页自己的品牌条和 hero。
- **侧边栏 / 检查器**：统一实现一个 `SplitLayout` 组件，负责拖宽、收起、记住状态（按模块存在 localStorage），窄屏时变成覆盖层。精读现有的 `assistant-resize-handle` 可以作为它的基础。
- **介绍文字**：只出现在空状态里，比如“建立第一个研究主题”“导入英文 LaTeX”。帮助性的长段落收进“?”弹出层。

### 3.2 弹层的使用规则

| 容器 | 用途 | 例子 |
|---|---|---|
| **弹出层 Popover** | 即时生效的小调节，点外面就关 | Aa 排版、朗读语速、引擎状态 |
| **检查器 Inspector** | 跟当前选中对象相关、需要长时间看着的信息 | 解读、笔记、批注、详情 |
| **Sheet / 对话框** | 需要确认的一次性操作 | 新建项目、导入、提交本轮、新建 Studio 任务 |
| **设置** | 跨会话保留的默认值和凭据 | 引擎、服务、模块默认值 |
| **Toast** | 结果反馈，可以附一个操作 | 已保存、设置已生效、撤销 |

不再用 `<details>` 收纳主功能，`<details>` 只留给“高级选项”。

### 3.3 视觉

- 浅色主题下，导航栏用深色（现状）没问题。macOS 26 的做法是侧边栏用浅色半透明，**如果以后封装成桌面应用（Tauri / Electron），建议改成浅色侧边栏**，让内容层成为视觉重心。
- 统一一套颜色变量，放进 `client_shell.css`；目前各模块 CSS 都有自己的 `--accent`。
- 检查器标签、工具栏按钮用图标加短文字。窄屏时只保留图标，用 tooltip 显示文字；精读工具栏已经有 `toolbar-compact-label` 这套做法。
