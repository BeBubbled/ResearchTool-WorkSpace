## 3. 兄弟超过 5 个的分叉（违反约束）

这些分叉没有被硬画：该节画成直线，线末端的圆点变红。

| 位置 | 节点类型 | 兄弟数 | 受影响的版本 | 建议 |
| --- | --- | --- | --- | --- |
| 「如何调参」下的段 | 段 | 15 | G2-keep、G2-omit、G3-keep、G3-omit | 把一部分并列段落归入 `###` 小节，或合并为列表 |

## 4. 边界情况与处理方式

| 情况 | 本文档中的出现 | 处理方式 |
| --- | --- | --- |
| 没有 `#` 或有多个 `#` | 有，4 个 # | 根 = 整篇文档；多个 `#` 各自成为第一层分叉（路径多一节） |
| 第一个标题之前的引言段 | 根下直接有 0 段 | 作为根的直接子段，按「段 i/n」计数，与同层标题分开计数 |
| 小节下直接是段落、没有 `###` | 见结构树 | 按实际层级画，不补空节，所以这些段的线比有 `###` 的段短一节 |
| 一个小节里既有段、又有子标题 | 见结构树 | 段与子标题分开计数；段在前、子标题在后 |
| 代码块 / 引用块 / 表格 | table 1 个 | 不画线，跟随上一段（该行左栏留空）；不计入兄弟数 |
| 列表被表格 / 代码块 / 引用块截成两段 | 「研究直觉」中被 table 截断 | 按 Markdown 解析结果处理：截断后的两个列表是各自独立的段，第二个列表的缩进层级丢失，成为顶层列表。如果原意是同一个嵌套列表，应在源文件里给表格加缩进，让它留在列表项内部 |
| 空的列表项 | 1 个：「超参数想当然了?」下的子项 | 丢弃，不计入兄弟数 |
| 没有内容的标题 | 统计学工具 | 该节没有线可画，只保留标题 |
| 一个列表项里有多个段落 | 规则 | 第一段带线；后续段落按「同一项的续段」处理，不画线 |
| 一个列表项里有多个子列表 | 规则 | 每个子列表各自独立编号 |
| 列表在 G1 / G2 中 | 规则 | 整个列表算一段，线只画在列表第一项；每一项各画线是 G3 的事 |
| keep / omit 的范围 | 规则 | 只作用于路径的最后一节：最后一节兄弟数为 1 时，omit 把它去掉 |
| 标题行本身 | 规则 | 不画线（handoff 只要求段和列表项） |

## 5. 对齐影响

| 版本 | 线的节数分布（节数: 行数） |
| --- | --- |
| G1-keep | 1: 25，3: 1 |
| G1-omit | 1: 25，2: 1 |
| G2-keep | 2: 25，4: 1 |
| G2-omit | 2: 25，3: 1 |
| G3-keep | 2: 21，3: 6，4: 16，5: 10，6: 7，7: 5，8: 1 |
| G3-omit | 2: 23，3: 6，4: 16，5: 9，6: 6，7: 6 |

每节宽度固定 16px，线都从左栏左边缘开始，所以第 k 节在所有行里 x 位置相同；节数不同只表现为线末端停在不同位置，不会错位。
代价是：路径较短的行，圆点停在更靠左的位置，读者要靠「节数」而不是「x 位置」来比较层级。
